# Milestone 4: Entitlements, billing and the financial silo

> **For the factory:** follow `superpowers:test-driven-development`. Each task is: failing test → see it fail → minimal code → see it pass → commit.

**Goal:**
- Tiers resolve from `entitlements.yaml`.
- Stripe billing runs on the parent web account only.
- A player token can never reach billing.
- The first Skill Tree milestone sends exactly one upgrade prompt, to the parent.
- The `premium-share` guardrail can be computed.

Covers REQ-005, the Basic side of REQ-004, GR-01, GR-06 and spec D5/D7.
**Architecture:** the `entitlements` and `billing` packages. The gateway filter checks role and entitlement (`ProposedSolution.md`, Interface Contracts).
**Repository:** `player-tiers-app`. Depends on Milestones 2 and 3.

## Task 4.1–4.2: Entitlements config

`src/main/resources/entitlements.yaml`, exactly as in `ProposedSolution.md`:

```yaml
plans:
  basic:   { price_usd: 9.00,  features: [skill_tree, player_card, drills, coach_feedback, parent_feed] }
  premium: { price_usd: 29.99, features: [skill_tree, player_card, drills, coach_feedback, parent_feed,
                                          video_library, wearable_sync, advanced_analytics] }
flags:
  video_library: { enabled: true }
  wearable_sync:    { enabled: true }
rules:
  progression_write_by_entitlement: false
  daily_xp_cap: 300
```

**Failing test** (`src/test/java/com/academy/tiers/entitlements/EntitlementsConfigTest.java`):

```java
package com.academy.tiers.entitlements;

import org.junit.jupiter.api.Test;
import java.math.BigDecimal;
import static org.assertj.core.api.Assertions.assertThat;
import static org.assertj.core.api.Assertions.assertThatThrownBy;

class EntitlementsConfigTest {
    Entitlements e = Entitlements.load("entitlements.yaml");

    @Test void pricesAndFeaturesMatchTheApprovedSolution() {
        assertThat(e.price("basic")).isEqualByComparingTo(new BigDecimal("9.00"));
        assertThat(e.price("premium")).isEqualByComparingTo(new BigDecimal("29.99"));
        assertThat(e.has("basic", "wearable_sync")).isFalse();
        assertThat(e.has("premium", "wearable_sync")).isTrue();
    }

    @Test void configThatLetsAPlanWriteProgressionIsRejected() {
        assertThatThrownBy(() -> Entitlements.parse("rules: { progression_write_by_entitlement: true }"))
            .isInstanceOf(InvalidEntitlementsException.class);
    }

    @Test void flagOffRemovesFeatureFromPremium() {
        var off = e.withFlag("wearable_sync", false);
        assertThat(off.has("premium", "wearable_sync")).isFalse();
    }
}
```

Run `./gradlew test --tests '*EntitlementsConfigTest'`. Expected: FAIL.

**Minimal implementation:**

- `Entitlements` is a SnakeYAML-backed record.
- `parse` rejects the config when `progression_write_by_entitlement` is not `false`.
- `has(plan, feature)` checks both the plan's feature list and the feature's flag.
- `EntitlementFilter` maps `@RequiresFeature("x")` handlers to `402 {"error":"tier_required"}`.

Run the same command. Expected: 3 PASS. Commit: `feat: entitlements from yaml with progression-write guard`.

## Task 4.3–4.4: Financial silo and Stripe (REQ-005, negative side)

**Failing test** (`src/test/java/com/academy/tiers/billing/FinancialSiloTest.java`):

- With a player token, `POST /billing/checkout` and `GET /billing/subscription` both return `403`.
- With a parent token, `POST /billing/checkout {"tier":"premium"}` returns `200` with a `checkout_url`.
- No endpoint in the player app's API (`/player/**`) returns a JSON field named `price`, `price_usd` or `checkout_url`. The test walks every `/player/**` mapping from `RequestMappingHandlerMapping`.

Second test, `StripeWebhookTest`:

- A signed `customer.subscription.updated` event moves the account to `premium` and emits `tier_changed`.
- Replaying the same event id changes nothing.
- A bad signature returns `400`.

Run `./gradlew test --tests '*FinancialSiloTest' --tests '*StripeWebhookTest'`. Expected: FAIL.

**Minimal implementation:**

- `BillingController` is restricted to `ROLE_PARENT`.
- `StripeGateway` is an interface, with the Stripe SDK in prod and a fake in tests.
- `StripeWebhookController` verifies the signature, stores processed event ids in `stripe_event(id primary key)`, and updates the tier.

Run the same command. Expected: PASS. Commit: `feat: parent-only stripe billing with idempotent webhook`.

## Task 4.5–4.6: Upgrade prompt and premium-share (REQ-005, positive side)

Also `PremiumShareTest`: with 10 active parent accounts and 2 on Premium, `PremiumShareQuery.share(academyId)` returns `0.20`.

**Minimal implementation:**

- `PremiumShareQuery` counts `tier='premium'` divided by the active parent accounts.
- Register `premium-share` under `## Proposed` in Product Office `analytics/metrics.md`.

Run the same command. Expected: PASS. Commit: `feat: parent-only upgrade prompt and premium-share guardrail`.
