# Milestone 5: Premium modules behind feature flags

> **For the factory:** follow `superpowers:test-driven-development`. Each task is: failing test → see it fail → minimal code → see it pass → commit.

**Goal:** Premium unlocks wearable sync and a curated YouTube training video library with the academy's multiple-choice tests. Each wearable data type needs the parent's opt-in. No footage of players is uploaded or stored. Each module runs behind one vendor adapter and a flag. Switching a flag off falls back to Basic features with no data loss. (REQ-004, CP-07, CP-08, GR-12; the `CEOApproval.md` delivery risk.)
**Architecture:** the `premium.wearable` and `premium.video` packages. The `WearableVendor` interface has Whoop and Fitbit adapters plus a fake. `YouTubeCatalog` has one production adapter and a fake.
**Repository:** `player-tiers-app`. Depends on Milestone 4. Pick the vendors before Task 5.2 and record them in the factory's decision log.

Run `./gradlew test --tests '*EntitlementTest'`. Expected: FAIL. The Milestone 2 stub still returns `202` without any checks.

**Minimal implementation:**

## Task 5.3: Curated YouTube training library

The academy curates the video links and writes a multiple-choice test for each, in parallel with the build (OQ-9). This task assumes the curated file is ready to import. Videos are embedded with YouTube's player by ID and never downloaded, per YouTube's terms. The library stores only the ID, metadata and questions.

**Failing test** (`src/test/java/com/academy/tiers/premium/VideoLibraryTest.java`):

- An academy admin posts `POST /library/import` with one video: `youtube_url` `https://www.youtube.com/watch?v=abc123XYZ00`, `skill_tree_node` `weak-foot`, and one question with 4 options and `answer_index: 2`.
  - `FakeYouTubeCatalog` reports the video as public and embeddable.
  - The response is `201` with `imported: 1`.
  - Re-importing the same batch returns `imported: 0, updated: 1`.
  - The `video_library` table has no file, blob or byte column.
- A batch where one row is a `https://vimeo.com/...` URL returns `422 not_youtube`, naming that row, and nothing from the batch is stored.
- A row where `FakeYouTubeCatalog` reports the video as private returns `422 not_embeddable`.
- A question with `answer_index: 5` returns `422 invalid_question`.
- A Premium player calling `GET /library/videos?node=weak-foot` gets the video and question. The response JSON contains no `answer_index`.
- A Premium player posting `POST /library/videos/{id}/answers {"answers":[2]}` gets `correct: 1`, `total: 1`, and XP under the daily cap. The Player Card attributes do not change (ADR-002).
- A Basic player calling `GET /library/videos` gets `402 tier_required`.
- After `AvailabilityJob.runOnce()`, with the fake catalog marking the video removed:
  - the video is hidden from players
  - it is flagged to the academy admin
  - its questions and past scores still exist

Run `./gradlew test --tests '*VideoLibraryTest'`. Expected: FAIL.

**Minimal implementation:**

- `LibraryImportController` (`ROLE_ADMIN`) validates every row first. It parses each YouTube URL into an ID and calls `YouTubeCatalog.lookup(id)`, which uses the YouTube Data API `videos.list` with `status` and `snippet`. The video must be public or unlisted, with `embeddable: true`. All rows are then upserted in one transaction.
- `video_library(id, youtube_id unique, title, skill_tree_node, questions jsonb, hidden)` and `quiz_attempt(player_id, video_id, correct, total, at)` are added in migration `V5__video_library.sql`.
- `LibraryController` strips `answer_index` from responses. Answer scoring awards XP through `DrillService`'s capped XP path and never writes attributes.
- `AvailabilityJob` is `@Scheduled` nightly and re-checks every video.
- The player app renders the YouTube IFrame player with the stored ID.

Run the same command. Expected: PASS. Commit: `feat: curated youtube training library with multiple-choice tests`.
