# Milestone 1: Identity, coach verification, roster and consent

> **For the factory:** follow `superpowers:test-driven-development`. Each task is: failing test → see it fail → minimal code → see it pass → commit.

**Goal:** a verified coach onboards a player directly, with no parent approval step. The link is active at once, the parent is notified, and the parent can revoke the link (REQ-001 as amended 2026-11-18, GR-07).
**Architecture:** the `verification`, `roster` and `audit` packages in the modular monolith (`ProposedSolution.md`, component diagram).
**Tech stack:** Java 21, Spring Boot 3, Gradle, JUnit 5, MockMvc, Testcontainers PostgreSQL, Flyway.
**Repository:** `player-tiers-app`. Every path below is relative to its root.

## Task 1.4: Academy onboards parents (OQ-8)

The academy onboards every parent itself, before coaches onboard players. Build it before player onboarding, because the `RosterLinkTest` setup calls it.

**Failing test** (`src/test/java/com/academy/tiers/roster/ParentOnboardingTest.java`):

- An academy admin posts `POST /academies/{id}/parents {"parents":[{"email":"parent@example.test","name":"Maria"},{"email":"p2@example.test","name":"Nikos"}]}`. The response is `201` with `created: 2`, and two `parent` accounts exist in that academy.
- Posting the same batch again returns `201` with `created: 0, existing: 2`, so the call is idempotent by email.
- A batch with one malformed email returns `422`, and no account from that batch is created.
- A coach token gets `403`.
- A coach onboarding a player with `parent_email: "unknown@example.test"` gets `422 parent_not_onboarded`, and no player or link is created.

Run `./gradlew test --tests '*ParentOnboardingTest'`. Expected: FAIL.

**Minimal implementation:**

- `ParentOnboardingController` is restricted to `ROLE_ADMIN` of the same academy. It validates every email first, then upserts by `(academy_id, email)` in one transaction.
- `RosterService.onboard` looks up that account and rejects the request when it is missing.
- Update `TestAccounts.activeLink(...)` so it onboards the parent through this endpoint before onboarding the player.

Run the same command. Expected: PASS. Commit: `feat: academy bulk-onboards parents; player onboarding links to them`.

## Task 1.5–1.6: Roster link (REQ-001)

**Failing tests** (`src/test/java/com/academy/tiers/roster/RosterLinkTest.java`):

```java
package com.academy.tiers.roster;

import com.academy.tiers.IntegrationTestBase;
import com.academy.tiers.verification.CoachVerificationService;
import org.junit.jupiter.api.Test;
import org.springframework.beans.factory.annotation.Autowired;
import org.springframework.jdbc.core.JdbcTemplate;
import org.springframework.test.web.servlet.MockMvc;
import java.time.LocalDate;
import static org.assertj.core.api.Assertions.assertThat;
import static org.springframework.test.web.servlet.request.MockMvcRequestBuilders.*;
import static org.springframework.test.web.servlet.result.MockMvcResultMatchers.*;

class RosterLinkTest extends IntegrationTestBase {
    @Autowired MockMvc mvc;
    @Autowired JdbcTemplate jdbc;
    @Autowired CoachVerificationService verification;
    @Autowired TestAccounts accounts;

    @Autowired FakeMailer mailer;

    static String onboardBody(String parentEmail, String name) {
        return "{\"player_first_name\":\"" + name + "\",\"dob\":\"2013-05-01\",\"parent_email\":\"" + parentEmail
             + "\",\"academy_consent_ref\":\"REG-2027-0042\"}";
    }

    @Test void verifiedCoachOnboardsPlayerAndParentIsNotified() throws Exception {
        var coach = accounts.coach();
        verification.record(coach, "DBS", "DBS-1", LocalDate.now().plusYears(1));
        mvc.perform(post("/rosters/{r}/players", accounts.rosterOf(coach)).with(accounts.coachToken(coach))
                .contentType("application/json").content(onboardBody("parent@example.test", "Alex")))
           .andExpect(status().isCreated())
           .andExpect(jsonPath("$.link_status").value("active"))
           .andExpect(jsonPath("$.parent_notified").value(true));
        assertThat(jdbc.queryForObject("select count(*) from roster_link where coach_id=? and status='active'", Integer.class, coach)).isEqualTo(1);
        assertThat(mailer.sentTo("parent@example.test", "player_onboarded")).hasSize(1);
    }

    @Test void expiredCoachOnboardingIsRejectedWith403AndNoLink() throws Exception {
        var coach = accounts.coach();
        verification.record(coach, "DBS", "DBS-2", LocalDate.now().minusDays(1));
        mvc.perform(post("/rosters/{r}/players", accounts.rosterOf(coach)).with(accounts.coachToken(coach))
                .contentType("application/json").content(onboardBody("parent2@example.test", "Sam")))
           .andExpect(status().isForbidden()).andExpect(jsonPath("$.error").value("coach_unverified"));
        assertThat(jdbc.queryForObject("select count(*) from roster_link where coach_id=?", Integer.class, coach)).isZero();
        assertThat(mailer.sentTo("parent2@example.test", "player_onboarded")).isEmpty();
    }

    @Test void parentRevokeRemovesCoachAccessOnNextRequest() throws Exception {
        var link = accounts.activeLink(mvc, verification);
        mvc.perform(delete("/links/{p}/coaches/{c}", link.playerId(), link.coachId()).with(link.parentToken()))
           .andExpect(status().isNoContent());
        mvc.perform(get("/players/{p}", link.playerId()).with(link.coachToken())).andExpect(status().isForbidden());
    }
}
```

Run `./gradlew test --tests '*RosterLinkTest'`. Expected: 3 FAIL (the endpoints are missing).

**Minimal implementation** (`src/main/java/com/academy/tiers/roster/`):

- `RosterController` handles `POST /rosters/{id}/players` and `DELETE /links/{p}/coaches/{c}`. There is no parent approval endpoint.
- `RosterService.onboard`:
  - checks `CoachVerificationService.isActive` first and throws `CoachUnverifiedException`, which maps to `403 {"error":"coach_unverified"}`
  - requires `parent_email` (`422 parent_email_required`)
  - creates the player account and an `active` link
  - links the player to the academy-onboarded parent account with that email (`422 parent_not_onboarded` if there is none, Task 1.4)
  - calls `Mailer.send(parentEmail, "player_onboarded")` with a sign-in link and a revoke link
  - leaves the player on Basic features whether or not the parent subscribes (OQ-8)
- `revoke` sets the status to `revoked`. The parent can revoke from the parent account, or by the signed revoke link in the notification.
- A `RosterAccessPolicy` bean makes every player-scoped read check for an `active` link.
- `Mailer` is an interface. `FakeMailer` in `src/test/java/com/academy/tiers/FakeMailer.java` records sends for tests.

Run the same command. Expected: 3 PASS. Commit: `feat: verified coach onboards players directly, parent notified and can revoke`.
