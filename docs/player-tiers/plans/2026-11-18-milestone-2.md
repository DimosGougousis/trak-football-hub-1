# Milestone 2: Progression, drills and the success metric

> **For the factory:** follow `superpowers:test-driven-development`. Each task is: failing test → see it fail → minimal code → see it pass → commit.

**Goal:** Player Card attributes change only on coach-signed tests. Drills earn XP under a daily cap. The `weekly-active-players` metric can be computed (REQ-002, CP-02, CP-03, GR-01, GR-02, GR-03, GR-11).
**Architecture:** the `progression` and `analytics` packages. `TestResultService` is the only writer of `player_attribute` (`ProposedSolution.md`, Decisions).
**Repository:** `player-tiers-app`. Depends on Milestone 1 (roster links and `TestAccounts`).

## Task 2.1–2.3: Single attribute write path (REQ-002)

**Failing tests** (`src/test/java/com/academy/tiers/progression/ProgressionTest.java`):

```java
package com.academy.tiers.progression;

import com.academy.tiers.IntegrationTestBase;
import com.academy.tiers.roster.TestAccounts;
import com.academy.tiers.verification.CoachVerificationService;
import org.junit.jupiter.api.Test;
import org.springframework.beans.factory.annotation.Autowired;
import org.springframework.jdbc.core.JdbcTemplate;
import org.springframework.test.web.servlet.MockMvc;
import static org.assertj.core.api.Assertions.assertThat;
import static org.springframework.test.web.servlet.request.MockMvcRequestBuilders.post;
import static org.springframework.test.web.servlet.result.MockMvcResultMatchers.*;

class ProgressionTest extends IntegrationTestBase {
    @Autowired MockMvc mvc;
    @Autowired JdbcTemplate jdbc;
    @Autowired TestAccounts accounts;
    @Autowired CoachVerificationService verification;

    @Test void coachSignedTestUpdatesAttributesAndAuditLog() throws Exception {
        var link = accounts.activeLink(mvc, verification);
        mvc.perform(post("/players/{p}/tests", link.playerId()).with(link.coachToken()).contentType("application/json")
                .content("{\"test_type\":\"sprint_20m\",\"results\":{\"pace\":71},\"signed_at\":\"2027-06-02T10:00:00Z\"}"))
           .andExpect(status().isCreated()).andExpect(jsonPath("$.attributes_changed[0]").value("pace"));
        assertThat(jdbc.queryForObject("select value from player_attribute where player_id=? and name='pace'", Integer.class, link.playerId())).isEqualTo(71);
        assertThat(jdbc.queryForObject("select count(*) from audit_log where action='attribute_changed' and subject_id=?", Integer.class, link.playerId())).isEqualTo(1);
    }

    @Test void premiumDrillAndWearableSyncChangeNoAttributes() throws Exception {
        var link = accounts.activeLink(mvc, verification);
        accounts.setTier(link.playerId(), "premium");
        accounts.optIn(link.playerId(), "wearable");
        var before = jdbc.queryForList("select name, value from player_attribute where player_id=?", link.playerId());
        mvc.perform(post("/players/{p}/drills", link.playerId()).with(link.playerToken()).contentType("application/json")
                .content("{\"drill_id\":\"weak-foot-01\",\"completed_at\":\"2027-06-02T17:00:00Z\"}"))
           .andExpect(status().isCreated()).andExpect(jsonPath("$.attributes_changed").isEmpty());
        mvc.perform(post("/players/{p}/wearables/sync", link.playerId()).with(accounts.deviceAdapterToken()).contentType("application/json")
                .content("{\"vendor\":\"test\",\"samples\":[{\"type\":\"resting_hr_bpm\",\"value\":58}]}"))
           .andExpect(status().isAccepted());
        assertThat(jdbc.queryForList("select name, value from player_attribute where player_id=?", link.playerId())).isEqualTo(before);
    }
}
```

Run `./gradlew test --tests '*ProgressionTest'`. Expected: FAIL, because the endpoints are missing. (Until Milestone 5, the wearable endpoint is a stub that returns `202` and stores samples only. The test pins the no-attribute rule now.)

- `DrillService.log(playerId, drillId, completedAt)`: inserts `drill_log` and emits `drill_logged`. Always returns `attributes_changed: []`.

Run the same command. Expected: 2 PASS. Commit: `feat: coach-signed tests are the only attribute write path`.

## Task 2.5: weekly-active-players

**Failing test** (`src/test/java/com/academy/tiers/analytics/WeeklyActivePlayersTest.java`): seed a roster of 5. Three players log 2 or more drills in ISO week 2027-W23, and one logs 1. `WeeklyActivePlayersQuery.share(rosterId, "2027-W23")` returns `0.60`.

Run `./gradlew test --tests '*WeeklyActivePlayersTest'`. Expected: FAIL.

**Minimal implementation** (`src/main/java/com/academy/tiers/analytics/WeeklyActivePlayersQuery.java`). The SQL:

```sql
select count(*) filter (where n >= 2)::numeric / nullif(count(*), 0)
from (select rl.player_id, count(dl.*) as n
      from roster_link rl
      left join drill_log dl on dl.player_id = rl.player_id and to_char(dl.day, 'IYYY-"W"IW') = ?
      where rl.status = 'active' and rl.coach_id in (select coach_id from roster where id = ?)
      group by rl.player_id) t;
```

Run the same command. Expected: PASS. Then save the SQL as `analytics/queries/weekly-active-players.sql` in Product Office (the metric's data source). Commit: `feat: weekly-active-players metric query`.
