01  The four things to raise first

Issues that need an answer before week 0

These come from the schema, not from speculation. The first is the one that sits in the critical path of the demo itself.

Blocker

A coach types a child's details before anyone has consented

UC-02 — the second step of the demo — has the coach build the squad by hand: name, position, shirt number, age group, stored in squad_players with no linked account. At that moment Trak holds identifiable data about a named minor, and neither the child nor the parent has been asked anything.

This is already flagged as a question in the July lawyer brief. It is now the first thing a coach does in the pilot, so it needs an answer rather than a discussion: does the academy's own consent cover it, does consent have to precede roster entry, or does the roster need to hold something less identifying until the child joins?

Blocker

Health-adjacent data on minors, in a table nothing writes to

wellness_logs stores mood, energy, sleep quality and free-text notes per child per day. Under GDPR that is plausibly special category data, which raises the bar considerably — explicit consent, and likely a DPIA.

Nothing writes to it. Wellness check-ins were cut from the pilot and WellnessCheck.tsx is reachable from no route. So the table is dormant: it carries the full legal weight of children's health data and delivers nothing.

Done. Confirmed empty and dropped, along with player_goals, which turned out never to have been removed despite the repo recording it as such. Trak therefore processes no special category data, and the DPIA question that would have followed does not arise.

Decide

Free text a parent cannot see

coach_assessments.private_note and admin_notes hold unstructured commentary about a named child, deliberately hidden from parents. That is a defensible product decision and a harder legal one: a subject access request would very likely reach it. Decide who may write there, what the retention period is, and what the answer is when a parent asks.

Decide

Behavioural analytics on minors

telemetry_events records what each user opens and when, including children. It is operational rather than product data and never surfaces in the app — but it is still behavioural data about minors and must be declared, with a retention period. It is the newest table and post-dates the July brief.

Twelve of the twenty tables hold data about a child

Deletion has to reach all twelve, and delete_my_account() is the mechanism. It has now been tested end to end, twice, against accounts carrying six matches each, coach assessments, awards and a linked parent: the account is removed, sign-in afterwards fails, and no roster rows remain. telemetry_events needs no explicit statement because it cascades from the auth user.

Testing it also found that the function referenced player_goals, a table a June migration claimed to have dropped but never did. Had that drop ever been applied, every account deletion would have failed — and nobody would have known, because until now nobody had run one. Both are fixed: the table is gone and the function no longer references it.

03  Beyond the tables

What else the DPA has to cover

Sub-processors

Supabase — database, authentication, storage, edge functions. Lovable — hosting and deployment. Sentry — error monitoring in production, and error reports can incidentally carry user identifiers. Google Gemini via the Lovable AI gateway — the coach assistant and the player feedback screen send prompt content off-platform.

That last one deserves attention: the feedback prompt includes a child's first name, position, six category scores and the coach's written note. Whether that leaves the EU, and on what basis, is a direct question for the lawyer.

Named roles

The pilot needs a named data owner — a person, not a company — and a decision on who is controller and who is processor between Trak and the academy. That answer changes who collects the parental consents and who answers a subject access request.

The academy holds the relationship with the families, which usually points to the academy as controller and Trak as processor. It is worth confirming rather than assuming, because the consent-collection burden follows it.

Retention

Nothing in the schema expires. Every table above keeps rows indefinitely, including telemetry and free-text notes about children. The DPA needs a retention period per category and an answer to what happens to a player's history when they leave the academy — which is the exact scenario Trak's pitch is built around.

Portability

Account deletion exists; data export does not. GDPR gives a right to portability alongside erasure, and the pilot's week-8 step promises to "hand the academy their data". Neither is currently possible through the product. For a pilot this size it can be a manual SQL export, but the commitment should be written down.

04  Order of work

What to do, and in what order

The first two are engineering and can be done today. The rest need the lawyer or the academy, so they should be started today even though they finish later.

  1. Drop wellness_logs once confirmed empty. Removes a special-category liability that currently buys nothing.
  2. Test the deletion path on a fully populated throwaway account, and extend it to telemetry_events if it does not already reach there.
  3. Send the lawyer this inventory with the four issues in section 01. Those are specific enough to be answered in one sitting, unlike the open questions in the July brief.
  4. Settle controller versus processor with the academy, because the consent-collection burden follows it — and consent cannot be drafted until it is settled.
  5. Draft the parental consent once 3 and 4 are answered. It must name the categories in section 02, the sub-processors in section 03, the retention period, and the deletion and export rights.
  6. Name the data owner — a person at the academy and a person at Trak.

Steps 3 and 4 are the ones that can move the pilot date. Everything else is hours of work under your own control. Send the email today even if the rest is unfinished.
